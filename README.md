# 루센트 현장점검

GitHub Pages용 정적 앱입니다.
서버 없이 각 기기에 점검 기록을 저장합니다.

## 실행과 배포

Node 22 이상에서 아래 순서로 실행합니다.

npm ci
npm test
npm run build

개발 확인은 `npm run dev`를 사용합니다.

GitHub Pages에는 `dist` 폴더의 내용만 배포합니다.

## 현장 목록 배포

관리자는 설정에서 로그인한 뒤 엑셀로 현장 목록을 등록하고 점검자를 설정할 수 있습니다.

엑셀 형식:

- B열: 현장명
- C열: 구역
- D열: 상세주소
- E열: 우선도
- F열: 작업주기

현장명, 구역, 상세주소는 필수입니다.

완전히 빈 행은 무시하며 필수 항목이 없는 행은 가져오지 않습니다.

관리자 메뉴의
`GitHub용 암호화 현장 파일 만들기`
기능으로 `site-directory.enc.json`을 생성합니다.

생성된 파일은 GitHub Pages의 `index.html`과 같은 위치에 올립니다.

원본 엑셀 파일은 GitHub에 올리지 않습니다.

직원은

`설정 → 공유 현장 목록 → 최초 연결`

에서 현장 목록 파일의 비밀번호를 처음 한 번 입력합니다.

같은 비밀번호로 새로운 현장 목록 파일을 배포하면 이후에는 다시 비밀번호를 입력하지 않아도 됩니다.

비밀번호를 변경한 경우 직원 기기에서도 새로운 비밀번호를 입력해야 합니다.

공유되는 정보는 현장 목록과 점검자 정보입니다.

점검 기록, 사진, 로그 등은 GitHub에 업로드하지 않습니다.

기존에 작성된 점검 기록에는 작성 당시의 현장 정보가 유지됩니다.

관리자가 현장 목록을 수정한 뒤 아직 새로운 현장 파일을 만들지 않은 상태라면 공유 목록 자동 갱신을 보류합니다.

엑셀 가져오기 시 동일한 현장명과 주소가 이미 존재하는 경우 중복으로 추가하지 않습니다.

기존 현장의 수정은 현장 관리에서 진행합니다.

## 데이터 저장

점검 기록은 사용 중인 브라우저의 로컬 저장소에 보관됩니다.

앱 데이터는 암호화하여 저장합니다.

관리자 PIN은 원문 그대로 저장하지 않습니다.

브라우저의 사이트 데이터를 삭제하면 저장된 점검 기록도 삭제될 수 있으므로 중요한 기록은 백업해 두는 것이 좋습니다.

다른 기기로 기록을 옮길 때는 앱의 암호화 백업 기능을 사용합니다.

같은 ID를 가진 데이터의 내용이 서로 다른 경우 자동으로 덮어쓰지 않습니다.

## 사진 및 출력

점검 사진은 앱에서 압축하여 저장합니다.

점검 결과는 PDF 또는 이미지 형태로 내보낼 수 있습니다.

여러 이미지 파일을 한 번에 내려받을 경우 브라우저에서 다중 다운로드 허용이 필요할 수 있습니다.

## 업데이트

새 버전을 배포할 때는 새로운 `dist` 파일을 올리고 기존의 `site-directory.enc.json`은 그대로 유지합니다.

앱에서 업데이트 안내가 표시되면 저장 중인 작업을 마친 뒤 새 버전으로 다시 열면 됩니다.

기존 점검 기록이 있는 브라우저에서는 사이트 데이터를 삭제하지 마세요.
