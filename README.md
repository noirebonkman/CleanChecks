# CleanChecks v0.7.0

## 반영 내용
- 파란색 중심 화면, 다크·시스템 모드, 모바일 메뉴와 아코디언 전환 효과를 적용했습니다.
- 작은 화면, 큰 글자, 키보드 탐색, 포커스 표시와 모션 줄이기를 보완했습니다.
- 점검자 이름 추가, 개인별 기록·백업, 작성 중 자동 저장, 수정 이력, 삭제 확인을 지원합니다.
- 점검 완료 확인 후 목록으로 돌아가며, 항목 선택 시 글자가 움직이지 않도록 했습니다.
- 현장 검색·선택과 엑셀 B~F열 읽기를 수정했습니다. 우선도와 작업주기는 비워둘 수 있습니다.
- 사진 썸네일·확대·삭제, JPEG 축소 저장을 지원합니다. 서명 기능은 없습니다.
- 원본 양식에 맞춘 2쪽 점검표를 출력합니다. 긴 내용은 이어지며 사진은 별도 페이지에 배치합니다. PNG/JPG는 점검표와 사진을 폴더별로 묶은 ZIP으로 받습니다.
- 개인 기록을 암호화해 옮길 수 있으며, 충돌하는 기록은 사용할 사본을 직접 선택합니다.
- 관리자 현장·로그 메뉴, 암호화 현장 JSON, 버전 표시·업데이트 확인·설치 안내를 반영했습니다.

## 업로드 순서
1. 기존 앱에서 개인 기록을 먼저 백업해 주세요. 브라우저 데이터는 삭제하지 마세요.
2. 업로드 ZIP을 풀고 **안의 파일과 폴더**를 GitHub 저장소 최상위에 덮어 올려 주세요.
3. 별도로 갱신한 현장 파일이 있다면 기존 파일을 보관하고 `data/site-directory.enc.json`에 최신 파일을 넣어 주세요. ZIP에는 이전에 준비한 42개 현장 목록이 암호화되어 있습니다.
4. 배포 후 앱 설정에서 업데이트를 확인하고 적용해 주세요. 설정 제목 옆과 하단 앱 정보에 **v0.7.0**이 표시됩니다.
5. 휴대폰에서 사진 촬영·선택과 JPG/PDF 저장을 한 번 확인해 주세요.

현장 원본 엑셀과 비밀번호 파일은 GitHub에 올리지 마세요. 기존 현장 파일 비밀번호를 그대로 사용합니다. 현장 목록 갱신은 개인 점검 기록을 다른 기기로 동기화하지 않습니다.

## 검증
- 자동 테스트와 TypeScript·배포 빌드를 통과했습니다.
- 엑셀 42개 현장, 기존 데이터 형식 호환, 암호화 저장, 기록 충돌 처리, 완료·수정·삭제를 확인했습니다.
- 사진 3200×1800 → 1600×900 JPEG 변환과 점검표·사진 ZIP 구성을 확인했습니다.
- 320~1440px 화면과 200% 글자에서 가로 넘침을 확인·수정했습니다.
- 자동 접근성 검사에서 검사 대상 구조의 위반은 0건이었습니다. 주요 밝은·어두운 색 조합 대비도 확인했습니다. 접근성 인증을 의미하지는 않습니다.
- 실제 휴대폰 카메라는 자동화 도구 연결 오류로 검증하지 못했습니다.

## 사용 범위
기록은 해당 브라우저에 저장됩니다. 다른 기기에서는 개인 백업을 가져와 사용합니다. 이름 선택과 관리자 PIN은 간단한 구분용이며 서버 인증은 아닙니다.

배포 저장소에서의 위치: data/site-directory.enc.json
소스 프로젝트에서의 위치: public/data/site-directory.enc.json

별도로 드린 ‘현장파일-비밀번호.txt’는 개인 보관용입니다. GitHub에는 올리지 마세요.

설정 → 공유 현장 목록 → 최초 연결(이미 연결했다면 연결 비밀번호 변경)에 이 비밀번호를 입력합니다. 기기에서 수정한 현장이 있다면 목록 교체 확인창이 나옵니다. 확인하면 현장 목록만 교체하며, 개인 점검표·사진·점검자 이름은 유지합니다.

이미 더 최신 현장 파일을 사용 중이면 이번 기본 파일 대신 기존 파일을 data/site-directory.enc.json에 넣으시면 됩니다. 이전 루트 위치의 site-directory.enc.json도 data 폴더에 파일이 없는 경우 계속 읽습니다.

# 루센트 현장점검

GitHub Pages용 정적 앱입니다.
서버 없이 각 기기에 점검 기록을 저장합니다.

## 실행과 배포

Node 22 이상에서 아래 순서로 실행합니다.

npm ci
npm test
npm run build

개발 확인은 `npm run dev`를 사용합니다.

GitHub Pages에는 `dist` 폴더의 내용만 배포합니다.

## 현장 목록 배포

관리자는 설정에서 로그인한 뒤 엑셀로 현장 목록을 등록하고 점검자를 설정할 수 있습니다.

엑셀 형식:

- B열: 현장명
- C열: 구역
- D열: 상세주소
- E열: 우선도
- F열: 작업주기

현장명, 구역, 상세주소는 필수입니다.

완전히 빈 행은 무시하며 필수 항목이 없는 행은 가져오지 않습니다.

관리자 메뉴의
`GitHub용 암호화 현장 파일 만들기`
기능으로 `site-directory.enc.json`을 생성합니다.

생성된 파일은 GitHub Pages의 `index.html`과 같은 위치에 올립니다.

원본 엑셀 파일은 GitHub에 올리지 않습니다.

직원은

`설정 → 공유 현장 목록 → 최초 연결`

에서 현장 목록 파일의 비밀번호를 처음 한 번 입력합니다.

같은 비밀번호로 새로운 현장 목록 파일을 배포하면 이후에는 다시 비밀번호를 입력하지 않아도 됩니다.

비밀번호를 변경한 경우 직원 기기에서도 새로운 비밀번호를 입력해야 합니다.

공유되는 정보는 현장 목록과 점검자 정보입니다.

점검 기록, 사진, 로그 등은 GitHub에 업로드하지 않습니다.

기존에 작성된 점검 기록에는 작성 당시의 현장 정보가 유지됩니다.

관리자가 현장 목록을 수정한 뒤 아직 새로운 현장 파일을 만들지 않은 상태라면 공유 목록 자동 갱신을 보류합니다.

엑셀 가져오기 시 동일한 현장명과 주소가 이미 존재하는 경우 중복으로 추가하지 않습니다.

기존 현장의 수정은 현장 관리에서 진행합니다.

## 데이터 저장

점검 기록은 사용 중인 브라우저의 로컬 저장소에 보관됩니다.

앱 데이터는 암호화하여 저장합니다.

관리자 PIN은 원문 그대로 저장하지 않습니다.

브라우저의 사이트 데이터를 삭제하면 저장된 점검 기록도 삭제될 수 있으므로 중요한 기록은 백업해 두는 것이 좋습니다.

다른 기기로 기록을 옮길 때는 앱의 암호화 백업 기능을 사용합니다.

같은 ID를 가진 데이터의 내용이 서로 다른 경우 자동으로 덮어쓰지 않습니다.

## 사진 및 출력

점검 사진은 앱에서 압축하여 저장합니다.

점검 결과는 PDF 또는 이미지 형태로 내보낼 수 있습니다.

여러 이미지 파일을 한 번에 내려받을 경우 브라우저에서 다중 다운로드 허용이 필요할 수 있습니다.

## 업데이트

새 버전을 배포할 때는 새로운 `dist` 파일을 올리고 기존의 `site-directory.enc.json`은 그대로 유지합니다.

앱에서 업데이트 안내가 표시되면 저장 중인 작업을 마친 뒤 새 버전으로 다시 열면 됩니다.

기존 점검 기록이 있는 브라우저에서는 사이트 데이터를 삭제하지 마세요.
