# 루센트 현장점검

GitHub Pages용 정적 앱. React + TypeScript + IndexedDB(AES-GCM). 서버 없이 기기에 점검 기록을 보관합니다.

## 실행과 확인

Node 22 이상에서 `npm ci`, `npm test`, `npm run build` 순서로 실행합니다. 개발 미리보기는 `npm run dev`입니다. `dist` 내용만 GitHub Pages에 배포합니다.

## 현장 목록 배포

관리자가 설정에서 로그인한 뒤 현장 엑셀을 등록합니다. 점검자는 사이드바에서 이름만 추가합니다. B열 현장명, C열 구역, D열 상세주소는 필수이며 E열 우선도와 F열 작업주기는 선택입니다. 완전히 빈 행은 무시하고 필수 항목이 누락된 행은 제외 사유를 보여줍니다.

관리자 메뉴의 ‘GitHub용 현장 파일 만들기’로 받은 `site-directory.json`을 저장소의 `JSON/site-directory.json`에 올립니다. 새 기기에서도 비밀번호 없이 자동으로 읽으며, 새 점검자는 동일한 공용 현장 목록을 사용합니다. 현장 목록을 받는 도중 새 점검을 시작하면 로드가 끝난 후 현장 선택을 엽니다.

공용 JSON은 현장 주소가 포함된 공개 파일입니다. 이 배포 방식은 사용자 요청으로 암호화 파일의 최초 비밀번호 입력을 없앤 방식이며 주소 접근 보호를 제공하지 않습니다. 개인 기록의 로컬 암호화와 백업 암호화는 유지합니다. 앱 실행, 화면 복귀, 온라인 복구 시 현장 목록을 확인합니다. 새 파일이 없으면 이전 `JSON/site-directory.enc.json`, `data/site-directory.enc.json`, 루트 암호화 파일도 읽을 수 있습니다. 이전 암호화 파일은 저장된 연결 비밀번호가 필요합니다.

공유 파일은 현장 목록만 배포하며 각 기기의 점검자 목록은 유지합니다. 과거 점검표에는 당시 현장 정보가 남으며 자동 변경되지 않습니다. 점검 기록·사진·로그는 GitHub에 업로드하지 않습니다. 다른 기기의 기록은 ‘내 점검 데이터 내보내기 / 개인 점검 데이터 불러오기’로 옮깁니다. 이전 버전 백업도 점검자별로 선택해 불러올 수 있습니다.

관리자가 수정하고 아직 내보내지 않은 목록이 있으면 자동 갱신을 보류합니다. 엑셀 가져오기는 중복 현장명+주소를 제외하고 추가합니다. 기존 현장의 수정은 현장 관리에서 진행합니다.

## 저장과 제한

- 로컬 데이터는 비추출 AES 키로 암호화합니다. 키와 암호문은 같은 브라우저 저장소에 있으며, 기기를 직접 제어하는 사람까지 차단하는 보안은 아닙니다.
- 점검자는 이름만으로 선택합니다. 관리자 PIN은 기존 방식으로 유지하며 5회 실패 시 30초 대기합니다.
- 상세 로그는 별도 RSA/AES 봉투 암호화로 저장하고 관리자 로그인 후 열람합니다. 앱 식별번호와 앱 내부 작업만 기록합니다. 관리자 초기 자격 증명은 사용자에게 별도 안내합니다.
- 브라우저 데이터 삭제 시 기록을 잃습니다. 백업 파일과 비밀번호를 별도 보관합니다.
- 사진은 압축하고 EXIF 메타데이터 없이 다시 인코딩합니다. JPG/PNG 선택은 첨부사진에도 적용합니다. PDF에서는 사진을 JPEG로 변환하여 별도 페이지로 배치합니다. JPG/PNG는 ZIP 묶음 또는 페이지·첨부사진별 직접 다운로드를 선택합니다.
- ZIP 내부 경로는 inspection/sheet_01.jpg와 photos/photo_01.jpg처럼 영문으로 고정해 압축 해제 도구의 한글 인코딩 차이를 피합니다. 직접 다운로드는 사용자가 원하는 파일의 버튼을 하나씩 누릅니다. PDF 한 파일 공유도 지원합니다.
- 같은 ID의 개인 기록 내용이 다르면 기기 내용 유지 / 파일 내용 사용을 기록별로 선택한 뒤 가져옵니다. 다른 점검자의 같은 ID는 덮어쓰지 않습니다.
- 자동 검사로 반응형 CSS 속성, 키보드 조작, 접근성 구조, 명암 대비, 모바일 메뉴를 검증합니다. 이번 버전의 실제 S25+ 화면·큰 글꼴·카메라·다운로드는 기기 확인이 필요합니다. 브라우저 미리보기 연결 시간 초과로 이번 버전의 실제 배치 검증은 완료하지 못했습니다.

## 업데이트

새 `dist` 파일을 올리되 별도로 갱신한 `JSON/site-directory.json`은 최신 파일을 유지합니다. 앱의 업데이트 안내가 뜨면 저장 후 새로 열기를 선택합니다. 이전 UI 시제품에서 처음 갱신할 때에는 해당 주소의 모든 탭을 닫고 다시 열어야 이전 서비스워커가 교체될 수 있습니다. 기록이 있는 브라우저의 사이트 데이터를 삭제하지 마세요.


## 1.0.0
- 기존 데이터베이스와 백업 형식을 유지합니다. 점검자는 이름으로 선택하고 관리자 PIN은 기존 값입니다.
- 기본정보 수정·사진 첨부는 기기 저장 결과를 확인한 후 성공을 안내합니다. 저장 실패 시 재시도·백업 경로가 유지됩니다.
- 사진 디코딩 대체 경로, JPG/PNG 첨부사진 변환, JPEG 기반 PDF 사진 페이지를 지원합니다.
- 화면 오류 시 기록을 지우지 않고 다시 열기 안내를 표시합니다. 테마 설정 저장소가 차단돼도 기본 테마로 시작합니다.
- 배포 ZIP에는 JSON 폴더를 넣지 않습니다. 기존 현장 목록을 유지해 주세요.
