# 루센트 현장점검

GitHub Pages용 정적 앱. React + TypeScript + IndexedDB(AES-GCM). 서버 없이 기기에 점검 기록을 보관합니다.

## 실행과 확인

Node 22 이상에서 `npm ci`, `npm test`, `npm run build` 순서로 실행합니다. 개발 미리보기는 `npm run dev`입니다. `dist` 내용만 GitHub Pages에 배포합니다.

## 현장 목록 배포

관리자가 설정에서 로그인한 뒤 엑셀과 점검자를 등록합니다. B열 현장명, C열 구역, D열 상세주소는 필수이며 E열 우선도와 F열 작업주기는 선택입니다. 완전히 빈 행은 무시하고 필수 항목이 누락된 행은 제외 사유를 보여줍니다.

관리자 메뉴의 ‘GitHub용 암호화 현장 파일 만들기’에서 8자 이상 비밀번호를 설정합니다. 내려받은 `site-directory.enc.json`을 공개 저장소의 `index.html`과 같은 위치에 올립니다. 원본 엑셀은 공개 저장소에 올리지 않습니다.

직원은 ‘설정 → 공유 현장 목록 → 최초 연결’에서 파일 비밀번호를 한 번 입력합니다. 앱 실행, 화면 복귀, 온라인 복구 시 새 목록을 확인합니다. 같은 비밀번호를 유지하면 새 현장 파일을 배포한 후 다시 입력하지 않습니다. 비밀번호를 바꾸면 직원 기기도 연결 비밀번호를 갱신해야 합니다.

목록은 현장·점검자 설정만 공유합니다. 과거 점검표에는 당시 현장 정보가 남으며 자동 변경되지 않습니다. 점검 기록·사진·로그는 GitHub에 업로드하지 않습니다. 다른 기기의 기록은 암호화 백업 파일로 옮깁니다.

관리자가 수정하고 아직 내보내지 않은 목록이 있으면 자동 갱신을 보류합니다. 엑셀 가져오기는 중복 현장명+주소를 제외하고 추가합니다. 기존 현장의 수정은 현장 관리에서 진행합니다.

## 저장과 제한

- 로컬 데이터는 비추출 AES 키로 암호화합니다. 키와 암호문은 같은 브라우저 저장소에 있으며, 기기를 직접 제어하는 사람까지 차단하는 보안은 아닙니다.
- PIN은 소금값과 PBKDF2-SHA256 기반 검증값으로 저장하며 5회 실패 시 30초 대기합니다. 4자리 PIN은 간단한 구분용입니다.
- 상세 로그는 별도 RSA/AES 봉투 암호화로 저장하고 관리자 로그인 후 열람합니다. 앱 식별번호와 앱 내부 작업만 기록합니다. 관리자 초기 자격 증명은 사용자에게 별도 안내합니다.
- 브라우저 데이터 삭제 시 기록을 잃습니다. 백업 파일과 비밀번호를 별도 보관합니다.
- 사진은 압축하고 EXIF 메타데이터 없이 다시 인코딩합니다. PDF에는 사진을 별도 페이지로, JPG/PNG에는 별도 사진 파일로 내보냅니다.
- 여러 이미지 다운로드는 브라우저의 다중 다운로드 허용이 필요할 수 있습니다. PDF 한 파일 공유가 가장 간단합니다.
- 같은 ID에 서로 다른 내용을 가진 백업은 자동 덮어쓰지 않고 중단합니다. 충돌 선택 병합 화면은 아직 제공하지 않습니다.
- 실제 S25+/Fold 시각 검수와 사진·출력파일 검수는 배포 후 확인이 필요합니다. 자동 테스트는 암호화, 관리자 메뉴, 점검 저장 및 갱신 보존을 검증합니다.

## 업데이트

새 `dist` 파일을 올리되 기존 `site-directory.enc.json`은 그대로 둡니다. 앱의 업데이트 안내가 뜨면 저장 후 새로 열기를 선택합니다. 이전 UI 시제품에서 처음 갱신할 때에는 해당 주소의 모든 탭을 닫고 다시 열어야 이전 서비스워커가 교체될 수 있습니다. 기록이 있는 브라우저의 사이트 데이터를 삭제하지 마세요.
